# 긱스플리터 전체 기능정의서 v1.1

Gemini 멀티모달 기반 대학생 생필품 공동구매 기획·모집·정산 서비스  
대상 플랫폼은 모바일 우선 웹 앱이다. 원본 v1.0의 기능 ID를 유지하고 누락된 요구사항에 F-11~F-20을 부여한다.

## 1. 문제와 목표

자취생과 기숙사생은 보관 공간과 초기 지출 부담 때문에 소용량 생필품을 선택한다. 대용량 상품을 나누면 단가를 낮출 수 있지만, 비교 기준을 찾고 수량과 돈을 나누고 참여자를 모집하는 데 손이 많이 간다.

긱스플리터는 쇼핑몰 캡처에서 상품 정보를 추출하고, 사용자가 확인한 비교 가격으로 실질 단가와 개인별 예상 절감액을 계산한다. 수령 장소와 참여 인원을 입력하면 바로 복사할 수 있는 모집글과 정산 안내문을 제공한다.

- **P0 · 아이디어톤 시연** — 캡처 또는 프리셋 → 값 확인 → 단가 비교 → 소분·정산 → 모집글 복사. 80분 제작, 3분 발표를 기준으로 핵심 흐름 한 건을 완주한다.
- **P1 · 운영 MVP** — 초안 저장, 카카오톡 공유, 수동 모집 관리, 송금·수령 확인, 완료 후 절약 기록을 지원한다. 송금은 참여자가 외부에서 진행한다.
- **P2 · 확장** — 교내 인증, 앱 내 매칭, 결제·보증금 연동, 증빙을 별도 출시 조건과 함께 검토한다.

## 2. 사용자와 권한

| 사용자 | 가능한 행동 |
|---|---|
| P0 방문자 | 로그인 없이 분석, 수정, 계산, 복사 |
| P1 방장 | 본인 초안 및 공구 생성·편집·취소, 참여 승인, 실제 비용 확정, 입금·수령 확인 |
| P1 참여자 | 초대 링크에서 공개 정보 확인, 신청·철회. 초대된 자기 행의 부담금 및 확정 안내 확인 |
| P2 운영자 | 제한된 권한으로 신고와 분쟁 처리, 처리 이력 기록 |

P1에서 방장은 인증된 계정으로 공구를 관리한다. 참여자는 공구별 초대 및 본인 확인을 거치며 초대 링크만으로 다른 참여자의 연락처, 입금 상태, 상세 수령 정보를 열람할 수 없다. 모든 조회·변경 요청에 서버가 공구와 역할을 확인한다.

## 3. 상세 기능

### P0 · 아이디어톤 시연

| ID | 기능 | 동작 및 완료 조건 |
|---|---|---|
| F-01 | 쇼핑몰 캡처 판독 | JPG·PNG·WebP 한 장을 업로드하고 미리보기에서 교체·삭제한다. Gemini가 제목, 선택 옵션, 구성과 규격, 표시 가격, 배송비·할인 정보를 읽는다. 옵션 또는 가격이 여러 개라면 후보를 보여주고 사용자가 선택한다. 흐릿하거나 가려진 필드는 미확인으로 표시한다. |
| F-02 | 시연 프리셋 | 롤휴지 30롤, 생수 2L×24병, 섬유유연제 4L 샘플을 제공한다. 샘플마다 비교 규격, 가격, 분할 단위가 포함된다. 시연 데이터임을 표시하고 사용자가 수정할 수 있다. |
| F-03 | 단가 비교 | 비교 단위를 정규화한 뒤 배송비·할인이 반영된 단가, 절감률, 개인별 절감액을 숫자와 막대그래프로 보여준다. 비교 기준이 없거나 호환되지 않으면 정산은 허용하고 절감 지표는 보류한다. 공동구매가 더 비싸면 차액을 그대로 표시한다. |
| F-04 | 소분 및 정산 | 방장을 포함한 2~4명을 지원한다. 기본 수량은 균등 배분하고 남는 수량은 방장에게 배정한다. 부담금은 각자의 수령 수량에 비례해 1원 단위로 계산한다. 1명이라도 최소 배분 단위를 받을 수 없다면 인원을 줄이도록 안내한다. |
| F-05 | 장소 설정 | 기숙사 로비, 학교 정문 등 공개 거점 추천과 직접 입력을 지원한다. 추천 칩은 사용자가 선택해야 적용된다. 장소 미정도 허용하며 모집글에 그대로 표시한다. |
| F-06 | 에브리타임용 모집글 | 제목과 본문에 상품, 모집 자리, 1인당 수량·부담금, 장소, 마감 또는 미정 상태, 신청 방법을 넣는다. 인원별 금액이 다르면 범위 또는 차이를 표시한다. 미확정 가격에는 예상임을 표시한다. 사용자가 미리 보고 복사한다. |
| F-09 | 장애 복구 | 분석 대기 표시, 타임아웃, 일시적 오류에 한한 제한 재시도, 수동 입력, 프리셋 전환을 제공한다. 입력한 값은 유지한다. 로컬 계산은 확보한 데이터로만 수행하고 추출에 실패한 이미지는 재업로드 또는 수동 입력으로 처리한다. |
| F-11 | 추출 결과 확인·수정 | 상품명, 구성 수량, 기준 단위, 결제 금액, 배송비와 할인 적용 여부를 검토하고 수정한다. 상품 단독 금액을 알 수 없는 혼합 장바구니는 상품별 금액 입력을 요청한다. 값이 바뀌면 정산표와 생성 문구를 같은 데이터로 갱신한다. |
| F-12 | 비교 상품 등록 | 소용량 상품의 가격, 구매 가능 수량, 단위, 출처 또는 사용자 입력 여부를 받는다. 출처는 링크나 캡처로 남길 수 있고 확인일을 표시한다. 같은 규격인지 확인하며, 규격이 불명확하면 비교 불가를 안내한다. |
| F-13 | 결과 공유 및 복사 복구 | 모집글을 복사하기 전에 최종 내용을 표시한다. 복사 성공·실패를 안내하며 권한 차단 시 텍스트를 선택해 직접 복사할 수 있다. 모집글은 외부 게시판에 사용자가 게시한다. |

### P1 · 운영 MVP

| ID | 기능 | 동작 및 완료 조건 |
|---|---|---|
| F-07 | 카카오톡 정산 안내 | 확정 총액, 참여자별 수량·부담금, 수령 일정과 장소를 텍스트로 생성한다. 기본 공유본은 별칭만 표기한다. 결제 정보와 상세 주소는 방장이 승인된 참여자에게 별도로 전달한다. |
| F-08 | 누적 절약 저금통 | 완료 공구 중 비교 기준과 실제 부담금이 확인된 건을 본인 기준으로 합산한다. 같은 공구를 중복 합산하지 않는다. 환불이나 정정이 생기면 최초 값을 다시 더하는 대신 해당 건을 수정하고 누적액을 재계산한다. |
| F-14 | 초안·공구 이력 | 초안 자동 저장, 다시 열기, 삭제와 내 공구 목록을 지원한다. 원본 이미지를 보관하지 않는 경우 확인된 입력 필드로 복원한다. 확정 이후에는 기록을 덮어쓰지 않고 변경 이력을 남긴다. |
| F-15 | 모집 관리 | 방장이 목표 인원, 신청 마감, 수령 후보 일시를 설정하고 참여자를 승인·제외한다. 동일 사용자의 중복 신청과 정원 초과 승인을 방지한다. 결원 발생 시 재모집하거나 인원을 변경하여 정산을 다시 계산한다. |
| F-16 | 주문 및 금액 확정 | 실제 주문 금액, 최종 수량, 주문 시점, 배송비를 입력한다. 예상과 실제 금액이 다르면 차이를 보여주고 승인된 참여자의 재확인을 받는다. 확정 후 변경이 필요하면 새 정산 버전을 만들고 정정 항목을 표시한다. |
| F-17 | 외부 송금 확인 | 참여자는 송금했다고 표시하고 방장은 외부 송금 내역을 확인한 뒤 입금을 확정한다. 중복 클릭이나 화면 재접속으로 입금 이력이 중복 기록되지 않는다. 부분입금, 추가 부담금, 환불 필요액은 별도 미해결 항목으로 표시한다. |
| F-18 | 수령·취소·변경 | 방장은 공개 거점에서 수령을 안내하고 각 참여자의 수령 여부를 기록한다. 품절·주문 취소·부분 환불·노쇼는 사유와 후속 조치를 기록한다. 유효한 참여 행의 입금·수령과 관련 정정이 해결되면 완료할 수 있다. |
| F-19 | 상태 안내·공유 갱신 | 모집·변경·마감·수령 안내를 화면과 공유 텍스트에 반영한다. 닫힌 링크는 모집 마감 또는 취소를 표시한다. 이전 정산 링크를 연 사용자는 최신 버전으로 이동할 수 있다. |
| F-20 | 용량형 소분 적합성 | 용량형은 포장 단위로 배분하는 것을 기본으로 한다. 단일 대용량 용기의 직접 소분은 사용자가 제품 표시사항, 계량 단위, 소분 용기를 확인했을 때만 지원한다. 확인이 없거나 제품 특성상 소분이 적합하지 않으면 밀봉 단위로 배분한다. |

### P2 · 확장

**F-10 교내 검증·실시간 매칭·결제 연동.** 교내 이메일 인증, 선택한 캠퍼스 내 공구방 탐색, 실시간 자리 갱신을 제공한다. 원본의 반경 500m 탐색은 위치 공유에 동의한 경우의 확장 옵션으로 검토한다. 보증금·에스크로는 결제 사업자 연동, 환불·분쟁·부분취소 정책, 운영 책임을 확정한 뒤 제공한다. 거래 참가자용 배분 내역서와 결제 사업자가 발행하는 결제 증빙을 각각 제공할 수 있다.

## 4. 핵심 계산 규칙

1. **결제 총액**은 해당 상품 금액과 실제 포함 배송비를 더하고 적용 가능한 상품 할인을 차감한 원화 정수다. 이미 할인된 가격 또는 배송 포함 가격에 동일 항목을 다시 반영하지 않는다. 조건부 쿠폰은 사용자가 적용 여부를 확인한다.
2. **정규화**에서 분할 단위와 비교 단위를 별도로 보관한다. 생수 2L×24병은 24병으로 배분하고, 용량이 다른 제품과 비교할 때는 총 48,000ml를 기준으로 단가를 구한다. 롤휴지는 규격이 같은 경우에만 롤당 비교하고, 길이 등이 다르면 확인 가능한 공통 규격으로 환산한다.
3. **단가**는 대용량 실결제 총액 ÷ 대용량 환산량과 소용량 실구매가 ÷ 소용량 환산량이다. **절감률**은 (소용량 단가 − 대용량 단가) ÷ 소용량 단가 × 100이다. 수량이 0 이하이거나 비교 단가가 0·미확인이면 절감률을 표시하지 않는다.
4. **수량 분배**는 총 분할 단위 Q를 N명에게 나눈 몫을 배정하고 나머지는 방장에게 더한다. 순서는 방장, 이후 참여 확정 순서다. 같은 분할 단위가 서로 다른 양을 뜻하는 혼합 상품은 자동 분배 대상에서 제외한다.
5. **정산**은 각 참여자의 이상 부담금 P × 개인 수량 ÷ Q를 내림한 뒤 남는 원을 소수 잔여가 큰 순서로 1원씩 배정한다. 동률이면 방장, 이후 확정 순서가 우선한다. 정산 합계는 실제 결제 총액과 같다. 계산에는 정수 또는 정확한 십진 연산을 사용한다.
6. **개인 절감액**은 개인 수령량을 소용량 단가로 환산한 기준 비용에서 개인 부담금을 뺀 값이다. 원 단위 반올림은 표시 마지막 단계에서 한다. 연간 환산은 사용자가 입력한 구매 횟수를 곱하고 예상치로 표기한다. 소용량을 실제로 구매하는 경우의 팩 단위 지출 차이는 별도 지표로 제공할 수 있다.

**검증 예시.** 휴지 30롤을 17,700원에 구매하고 소용량 6롤이 7,800원이라면 롤당 590원과 1,300원, 단가 절감률은 약 54.6%다. 4명이 나누면 방장 9롤·5,310원, 참여자 각 7롤·4,130원이다. 방장 기준 환산 절감액은 6,390원, 참여자 기준은 각각 4,970원이다. 30롤을 17,701원에 구매하면 방장 5,311원과 각 4,130원으로 합계가 일치한다.

## 5. 공구 상태와 변경 규칙

| 공구 상태 | 진입 및 전환 |
|---|---|
| 초안 | 입력 저장. 게시 요건이 갖춰지면 모집 중으로 전환 |
| 모집 중 | 신청·승인 가능. 방장이 승인 명단을 확인한 뒤 모집 마감. 정원 도달 시 추가 승인 차단 |
| 모집 마감 | 주문 및 조건 확정 준비. 주문 확정 전에는 재모집 가능 |
| 정산 중 | 실제 금액과 수량을 확정해 참여자에게 제시. 조건이 바뀐 경우 재확인 후 입금 확인 진행 |
| 수령 중 | 주문 상품 준비 후 수령 안내. 개별 입금·수령·환불 상태는 독립적으로 관리 |
| 완료 | 유효 참여자의 수령 및 미해결 금액 정리 확인 후 전환. 해당 공구의 실제 절약액 집계 |
| 취소 | 사유 기록 및 모집 종료. 이미 받은 금액이 있으면 환불 상태를 추적하고 해결 기록을 보존 |

모집 중 인원수나 금액 수정에는 수정 시각을 표시한다. 승인과 정원 갱신은 하나의 처리로 저장한다. 주문 이후 참여자 변경, 환불, 부담금 변경은 이전 정산 버전과 입금 이력을 보존한다. 이미 접수된 입금은 취소되지 않으며 환불 결과를 별도로 기록한다.

## 6. Gemini 및 데이터 명세

- 원본의 Gemini 3.8 Flash는 모델 후보로 유지한다. 착수 시 사용 환경에서 이미지 입력과 구조화 출력 지원을 확인하고 모델 이름을 서버 설정으로 관리한다.
- 추출 요청은 이미지와 추출 규칙을 전송한다. 모델은 이미지 속 문구를 분석 대상 데이터로 취급한다. 방장 입력, 연락처, 수령 장소, 입금 데이터는 상품 추출에 필요하지 않다.
- 추출 규칙은 화면에 보이는 값만 반환하고 불확실한 값은 null로 반환하도록 지정한다. 상품 수량, 배송비, 쿠폰 가격의 적용 조건을 임의로 채우지 않는다. 모델 결과는 스키마와 범위를 검증한 뒤 사용자 확인 화면에 표시한다.
- 추출 필드는 `fullTitle`, `shortName`, `selectedOption`, `packCount`, `unitsPerPack`, `netAmountPerUnit`, `unitName`, `displayedTotalPrice`, `shippingFee`, `discountAmount`, `priceCandidates`, `evidence`, `unresolvedFields`로 구성한다. 가격 후보는 원화 금액, 가격 유형, 적용 조건, 화면 근거 문구를 포함한다.
- 비교 가격과 연간 구매 횟수는 출처가 있는 프리셋 또는 사용자 입력에서 확보한다. 가격 계산은 앱이 담당한다. 모집글에 Gemini를 활용하는 경우 확인된 필드를 바탕으로 문장만 구성하고 금액이나 일정을 검증한 뒤 출력한다. 장애 시 동일 필드로 작성한 템플릿을 사용한다.
- 운영 데이터는 사용자, 상품 분석, 비교 기준, 공구, 참여, 정산 버전, 송금·환불 이벤트, 수령 기록으로 구성한다. 정산 버전에는 계산에 사용한 가격과 단위, 행별 수량·금액을 스냅샷으로 보관한다.

## 7. 개인정보·안정성·접근성

- 업로드 전에 주문번호, 실명, 연락처, 상세 주소가 포함된 결제 화면을 자르거나 가릴 수 있도록 안내한다. 업로드 파일의 실제 형식과 크기를 검증하며 프리셋 및 수동 입력도 제공한다.
- 모델 키는 서버에 보관한다. 업로드 이미지는 처리 목적에 필요한 기간에 한해 임시 취급하고 완료 또는 실패 후 정리한다. 운영 전 보관 기간과 삭제 절차를 확정한다. 오류 로그에는 원본 이미지와 연락처를 담지 않는다.
- 분석 중 입력을 교체하면 이전 응답을 폐기한다. 중복 요청을 제한하고 사용자별 호출 한도를 둔다. 네트워크가 불안정하면 확인된 입력과 로드된 프리셋으로 가능한 계산 상태를 안내한다.
- 오류 메시지는 막힌 필드와 처리 방법을 보여준다. 그래프에는 숫자와 단위를 함께 표시하고, 증가·감소를 색으로만 표현하지 않는다. 분석·복사 결과는 보조 기술이 읽을 수 있는 상태 메시지로 제공한다.
- 원본의 프리셋 1.2초, 실제 이미지 결과 4초, 모집글 포함 핵심 결과 5초는 성능 목표로 관리한다. 대상 기기와 네트워크를 기록하고 버튼 클릭부터 화면 렌더링까지 측정한다.
