# 긱스플리터 백엔드 인수인계

## Frontend 전달용: P0 연동

**완료 기준:** 로그인 없이 프리셋·직접 입력·쇼핑몰 캡처 중 하나로 시작해 입력 확인 → 단가 비교 → 2~4인 정산 → 에브리타임 모집글 복사까지 완료한다. 아래는 **현재 API** 기준이며, [PRD v1.1 전환 계획](./plan-backend.md#p0--로그인db-없는-시연-경로)과 구분한다.

### 화면 흐름

| 단계 | Frontend 동작 |
| --- | --- |
| 상품 선택 | `GET /api/presets`의 `product`로 편집 폼을 채운다. 프리셋 가격은 실시간 시세가 아닌 시연 데이터로 표시한다. 직접 입력도 같은 폼을 사용한다. |
| 캡처 판독 | JPG·PNG·WebP 한 장(최대 5 MiB)을 미리 보여주고 교체·삭제할 수 있게 한다. 방장 포함 인원을 선택한 뒤 `POST /api/products/extract`에 `FormData`로 `image`와 `people`(`"2"`~`"4"`)을 보낸다. `Content-Type`은 브라우저에 맡긴다. 업로드 전 주문번호·실명·연락처·상세 주소를 가리도록 안내한다. |
| 값 확인 | 판독 `200`도 자동 확정하지 않는다. 상품명, 최종 결제 예정가, 수량, 단위와 소포장 가격·수량을 편집 폼에서 확인한다. 이미지 교체·삭제 또는 새 요청 후에는 이전 판독 응답을 적용하지 않는다. |
| 결과 계산 | `POST /api/analyses`에 JSON `{ product, people, location? }`을 보낸다. `people`은 정수 `2`~`4`. 입력을 변경하면 단가·정산표·모집글을 동일한 새 응답으로 갱신한다. |
| 모집글 복사 | `recruitment.title`과 `recruitment.body`를 줄바꿈 그대로 미리 보여준다. 복사 성공·실패를 알리고, 권한 차단 시 텍스트를 선택해 직접 복사할 수 있게 한다. 외부 게시판에 자동 게시하지 않는다. |

개발 서버의 `/api`를 `http://127.0.0.1:3001`로 프록시한다. 전체 요청·응답 필드는 [프론트 연동 API](./plan-backend.md#프론트-연동-api)를 따른다. Gemini 키는 캡처 판독용이며 프론트에 넣지 않는다.

### 입력·결과 처리

- `422 MANUAL_CORRECTION_REQUIRED`: 유효한 부분 판독값(`product`)은 보존하고 `fields`에 해당하는 항목을 수정 대상으로 표시한다. 보정 후 이미지를 다시 보내지 않고 `/api/analyses`를 호출한다. `422 INVALID_ANALYSIS_INPUT`도 `fields`를 해당 폼 항목에 연결한다.
- 업로드 `400 EXPECTED_ONE_IMAGE`·`413`·`415`는 개수·크기·형식 안내 후 파일 재선택으로 연결한다. `502`·`503`·`504` 또는 네트워크 오류에서는 입력을 유지해 직접 입력이나 프리셋으로 이어간다. 로딩과 실패를 구분해 표시한다.
- 프리셋의 `sources.small.label`·`url`, 판독의 `comparisonSource.kind`(`SCREENSHOT`·`PRESET`) 또는 사용자 입력 여부를 비교 기준 옆에 표시한다. 분석 응답에 출처가 없으므로 프론트에서 유지하되 비교값을 수정하면 기존 출처를 붙이지 않는다. `PRESET`은 규격 검증을 보장하지 않는다. 규격이 다르거나 불명이면 확인된 비교값으로 수정한 뒤 분석한다. 모집글에도 절감률이 포함되므로 잘못된 비교 결과는 복사 대상으로 제공하지 않는다.
- `bulkUnitPrice`와 `smallUnitPrice`는 이미 `displayUnitQuantity` 기준이다. `100ml당`처럼 단위를 붙이고, 정산 수량에는 원래 `product.unitName`을 쓴다. 절감률이 음수면 `소포장 대비 더 비쌈`으로 표시한다. `instantSavings`와 `annualSavings`는 방장 기준 예상치이며 반올림은 표시할 때만 한다.
- 정산표는 `settlements`의 `ORGANIZER`·`MEMBER`를 각각 방장·공구원으로 표시한다. 수령 장소는 추천 장소 선택 또는 직접 입력을 받는다. 표시와 모집글에는 응답의 `location`을 사용한다. 생략하거나 비우면 현재 서버는 `행복기숙사 1동 로비`를 반환한다.

### 현재 API로 지원하지 않는 PRD v1.1 동작

- **수량 비례 부담금·공구원 절감액:** 현재는 수량과 금액을 각각 균등 분할하고 두 나머지를 방장에게 준다. 30롤·17,701원·4명이라면 현재 응답은 방장 9롤·4,426원, 공구원 각 7롤·4,425원이다.
- **비교가 없는 정산:** 비교 수량·가격이 없으면 분석 API가 `422`를 반환한다. 분할 단위와 비교 단위를 독립 지정할 수도 없다.
- **상세 판독·모집 조건:** 가격 후보, 배송비·할인 내역, 장소 미정, 모집 마감은 현재 계약에 없다. 프론트에서 임의의 값이나 별도 정산으로 맞추지 않는다.

### 인수 확인

1. Gemini 키 없이 프리셋과 직접 입력에서 복사까지 진행하고, 2·3·4인 배분의 수량·금액 합계가 원본과 일치하는지 확인한다.
2. 실제 캡처로 판독·수정을 확인한다. 비교가 누락, 파일 오류, 타임아웃에도 입력이 유지되고, 이미지 교체 뒤 이전 응답이 폼을 덮지 않아야 한다.
3. 모바일 브라우저에서 100ml 단가, 가격 역전, 복사 실패 후 직접 복사를 확인한다. 버튼 클릭부터 결과 렌더링까지 프리셋 1.2초, 실제 이미지 4초를 목표로 측정한다.

## 현재 상태

- 로컬 구현은 `d7625ad`의 DB 없는 P0 API다. Node.js 24 이상, 외부 npm 의존성 없음. 프리셋 3종, 단가·정산, 모집글, Gemini 판독·수동 보정 경로가 있다. 기존 코드는 v1.0 기반이며 v1.1과 달라지는 동작은 [구현 계획](./plan-backend.md)에 분리했다.
- `feat/backend-gigsplitter`에 `origin/main`의 `a3c5934`를 통합했다. 새 ERD 5개 테이블과 두 버전의 PRD를 함께 참조할 수 있으며, PRD v1.1의 모델 표기도 Gemini 3.8 Flash로 갱신됐다.
- 독립 검증에서 500ml × 24병에 2L × 24병 비교가가 잘못 적용되고, 30m/롤과 33m/롤이 환산 없이 비교되는 문제가 확인됐다. 비교 규격과 출처 검증을 다음 코드 작업의 첫 단계로 둔다.

## 실행과 확인

```sh
cd backend
npm test
npm start
```

`http://127.0.0.1:3001/api/presets`에서 프리셋을 확인한다. 이미지 판독이 필요하면 `backend/.env`에 `GEMINI_API_KEY`를 설정한 뒤 다시 시작한다. `PORT`, `HOST`, `GEMINI_MODEL`은 선택이다. 키는 저장소에 올리지 않고, 배송지 등 개인정보가 담긴 화면은 가린 후 업로드한다. 프리셋·정산·문구 생성은 키 없이도 동작한다.

`npm test`는 현재 v1.0 기반 정산과 보정 경로를 확인한다. 독립 검증에서 5개가 통과했지만 Gemini 응답은 대체했다. 실제 판독·쿠폰 정확도·화면 시간은 키를 설정한 환경에서 별도로 확인한다. 현재 기본 모델은 `gemini-3.5-flash-lite`로, [`gemini-3.8-flash` 전환과 응답 갱신은 계획에 반영](./plan-backend.md#프론트-연동-api)했다.

## 다음 작업자가 할 일

1. 프리셋 오매칭·환산 오류, 비교가 없어도 정산하는 경로, v1.1 수량 비례 정산부터 작업한다.
2. 프론트와 판독 후보·사용자 보정·모집 문구 계약을 맞춘다. `gemini-3.8-flash` 설정으로 실제 이미지와 결과 렌더링 시간을 검증한다.
3. P1 마이그레이션 전에 ERD 담당자와 [운영 스키마 차이](./plan-backend.md#p1--erd-기반-운영-저장)를 합의한다. P0는 그 결정과 별도로 로그인·DB 없이 유지한다.

## 후속 합의 사항

| 결정할 항목 | 확인할 내용 |

| 비교 데이터 | 시연 가격의 개별 판매 페이지·확인일·할인 조건이 필요하다. 독립 검증에서는 GS SHOP의 삼다수 소포장만 확인했고 나머지 판매 페이지는 접근 제한 등으로 재확인하지 못했다. |

| 배포 | 현재 서버는 로컬 루프백에서 실행한다. 과금되는 판독 API를 외부에 열기 전 접근 제어를 정한다. |
| ERD 정합성 | 수동 분석과 비교 출처, 참여 승인, 상태 전환, 버전·입금·수령 이력, 완료 공구별 절약 기록 키를 확정한다. |

합의된 API나 계산 규칙은 계획서에 반영하고, 이 문서에는 현재 상태와 다음 작업을 남긴다.
