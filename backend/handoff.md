# 긱스플리터 백엔드 인수인계

## 현재 상태

- [PRD v1.0](https://github.com/enderpawar/Gwayook-team6/blob/docs/erd/docs/GigSplitter-PRD-v1.0.pdf)의 ERD 비의존 P0 API를 구현했다. [구현 계획](./plan-backend.md)에 실제 요청·응답 계약이 있다.
- Node.js 24 이상, 외부 npm 의존성 없음. 프리셋 3종, 단가 비교·정산, 에브리타임 모집글 생성, Gemini 이미지 판독·수동 보정 경로가 있다. DB와 사용자 계정은 추가하지 않았다.
- 새 ERD는 다른 팀원이 작성 중이다. `origin/docs/erd`의 기존 `docs/ERD.md`는 택시·배달 합승 모델이므로 백엔드 구현 기준으로 사용하지 않는다.

## 실행과 확인

```sh
cd backend
npm test
npm start
```

`http://127.0.0.1:3001/api/presets`에서 프리셋을 확인한다. 이미지 판독이 필요하면 `backend/.env`에 `GEMINI_API_KEY`를 설정한 뒤 다시 시작한다. `PORT`, `HOST`, `GEMINI_MODEL`은 선택이다. 키는 저장소에 올리지 않고, 배송지 등 개인정보가 담긴 화면은 가린 후 업로드한다. 프리셋·정산·문구 생성은 키 없이도 동작한다.

`npm test`는 2·3·4명 정산, 100ml 단가, 음수 절감률, 보정 후 재분석을 확인한다. 판독 응답은 테스트에서 대체했으며 실제 Gemini 호출, 쿠폰 화면 판독 정확도, PRD의 4초 목표는 키를 설정한 환경에서 별도로 확인해야 한다.

## 다음 작업자가 할 일

1. 프론트에서 `/api` 프록시를 설정하고 프리셋·수동 입력·이미지 판독 세 흐름을 [API 계약](./plan-backend.md#프론트-연동-api)에 연결한다.
2. 실제 쇼핑몰 캡처로 결제 예정가·수량과 수동 보정 흐름을 확인하고 결과 화면까지의 시간을 측정한다.
3. 새 ERD가 나오면 로그인·서버 영속화가 필요한 기능을 대조한다. PRD의 P0 모집글은 복사용 문구이며, 계정·모집글·참여 저장이나 실제 매칭을 요구하지 않는다.

## 후속 합의 사항

| 결정할 항목 | 확인할 내용 |
| --- | --- |
| 비교 데이터 | 프리셋 가격은 `sources`에 기록한 판매처의 표시가이며 실시간 시세가 아니다. 휴지·유연제는 다른 브랜드의 동종 소포장과 비교하므로 화면에 비교 상품명과 출처를 표시한다. 프리셋에 매칭되지 않는 이미지의 비교가는 사용자가 확인한다. |
| 프론트 연동 | 단가·절약액 표시 자릿수, `fields` 기반 수동 입력, 타임아웃 이후 동작을 맞춘다. |
| 배포 | 현재 서버는 로컬 루프백에서 실행한다. 과금되는 판독 API를 외부에 열기 전 접근 제어를 정한다. |
| 새 ERD | P1 절약액 누적을 서버에 저장할지 정한다. 저장한다면 사용자 범위, 분석 건 식별자, 중복 방지 제약을 ERD 담당자와 맞춘다. |

합의된 API나 계산 규칙은 계획서에 반영하고, 이 문서에는 현재 상태와 다음 작업을 남긴다.
