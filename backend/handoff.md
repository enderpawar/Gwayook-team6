# 긱스플리터 백엔드 인수인계

## 현재 상태

- [PRD v1.0](https://github.com/enderpawar/Gwayook-team6/blob/docs/erd/docs/GigSplitter-PRD-v1.0.pdf)을 검토해 [구현 계획](./plan-backend.md)에 P0 작업 순서와 프론트 연동 초안을 정리했다.
- `backend/`에는 계획·인수인계 문서만 있다. 서버, API, DB 마이그레이션은 아직 구현하지 않았다.
- 새 ERD는 다른 팀원이 작성 중이다. `origin/docs/erd`의 기존 `docs/ERD.md`는 택시·배달 합승 모델이므로 백엔드 구현 기준으로 사용하지 않는다.

## 다음 작업자가 할 일

1. 백엔드 런타임을 팀과 합의해 `backend/`를 초기화한다. DB 연결이나 Gemini 호출 없이 실행되는 단가·정산 계산부터 작성한다.
2. 계획서의 2·3·4명 정산 기준으로 합계 보존과 방장 나머지 배정을 검증한다. 프리셋과 수동 입력을 같은 계산 경로에 연결한다.
3. 프론트 담당과 API 초안을 확정해 모집글 생성까지 연동한다. 다음으로 Gemini 판독, 수동 보정 경로, 실이미지 응답 시간을 확인한다.
4. 새 ERD가 나오면 로그인·서버 영속화 요구가 실제로 확정됐는지 대조한다. PRD는 P0에서 계정과 모집글·참여 저장을 요구하지 않는다. 실제 참여 매칭을 생성 문구와 혼동해 추가하지 않는다.

## 착수 시 확인할 결정

| 결정할 항목 | 확인할 내용 |
| --- | --- |
| 백엔드 런타임 | 저장소와 PRD에 지정된 런타임이 없다. 팀이 유지할 스택과 로컬 실행 명령을 합의한다. |
| 비교 데이터 | 프리셋 3종의 실측 가격·수량과 이미지 모드 소용량 시세의 출처를 정한다. PRD의 JSON 예시 가격을 실측 데이터로 간주하지 않는다. |
| 정산 표시 정책 | 절약액·단가·절감률의 표시 자릿수와 반올림 규칙, 수량이 인원보다 적어 공구원 배분량이 0인 입력의 처리 기준을 정한다. 정산표의 원 단위 합계 규칙은 변경하지 않는다. |
| 프론트 연동 | 요청 필드, 이미지 크기 제한, 판독 실패 응답 형식과 타임아웃·오프라인 처리 주체를 합의한다. |
| 새 ERD | P1 절약액 누적을 서버에 저장할지 정한다. 저장한다면 사용자 범위, 분석 건 식별자, 중복 방지 제약을 ERD 담당자와 맞춘다. |

위 결정 중 DB 관련 항목은 계산·문구 생성 착수의 선행 조건이 아니다. 합의된 API나 계산 규칙은 계획서에 반영하고, 이 문서에는 현재 상태와 다음 작업을 남긴다.
